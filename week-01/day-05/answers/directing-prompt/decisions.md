# Answer: the directing prompt for run 2

`run2-prompt.txt` here is the course's prompt. `commands.sh` copies it into `lab` and runs the check.

| Part | Answer | Reason |
|---|---|---|
| Context | read model.py, prompts/system.txt and schema/output.schema.json. The tests use the replies in tests/recorded/. | The function sends `prompts/system.txt` through `model.py` to the model, and checks each reply against `schema/output.schema.json`, run 1's schema, which holds the type of each field. The tests use the two recorded replies. Without these paths, the agent guesses where the files are (section 5.1). |
| Constraints | The tests call no model. Do not edit anything outside extractor.py and tests/test_extractor.py. Do not log note text. | Each rule changes or keeps one of run 1's (section 5.1, run 1's table). The Goal's function calls the model, whose reply can change, so the rule on the model now covers only its tests: they use the replies recorded earlier (the Opening). The agent adds the Goal's two files and edits nothing else: if it changed run 1's files or the recorded replies, wrong code could pass. Claude Code's settings already deny edits to `tests/test_schema.py`, but Codex does not read them, so the prompt gives the bounds to either agent. A log line with note text copies taxpayer data (day 1, section 1.2). The schema now holds run 1's types, so the prompt leaves them out. |
| Done-when | pytest tests/test_extractor.py passes. It includes one reply that must fail (amount_in_question missing) and note 0102, for which the function must return amount_in_question null. | Anyone can run the command, without trusting the agent (section 5.1). The reply that must fail catches an extractor that accepts any reply. Note 0102 has a recorded reply and names no amount, so its test catches an extractor that supplies one (the Opening). Note 0147, the other recorded note, names 18,400. |

The check also accepts more paths in `lab` in Context, such as `docs/fields.md`, a folder for a file, such as `schema/`, or `tests/test_schema.py` as a pattern to copy. In Constraints it accepts a list of what the agent may not change (`schema/`, `tests/test_schema.py` and `tests/recorded/`), "Keep X as they are.", "Treat X as read-only.", "Only the course team edits X." or "The agent may change only extractor.py and tests/test_extractor.py."; for the model, "The tests use the recorded replies." or "The tests give the function a fake ask()."; and run 1's types, kept or left out. It never accepts run 1's "Do not call any model.": the Goal's function calls the model. In Done-when it accepts any command that passes on the course's run 2 (the course folder's `lab-states/run2/`) and fails on both wrong runs (the exercise's `files/wrong-run-2/`): one extractor accepts every reply that is JSON, and the other puts 0 in place of null. Two such commands are `python3 -m pytest -q tests/` and `pytest tests/test_extractor.py -k amount`, written in backticks, in quotation marks or in plain text. As the reply that must fail, it accepts one that is not JSON, has a field too many, or has an amount as text, but not one that the schema accepts, such as `amount_in_question` null or 0: from the reply alone, the function cannot tell that 0 is wrong for note 0102.

Passing shows that your done-when tells the course's run 2 from two wrong runs, not that every wrong run fails it. The done-when runs the tests that the agent writes, so weak tests, or tests changed until they pass, still pass it (section 5.2). It also cannot judge the words of `issue` or `next_action`, which the model chooses, and a new run can choose others. A run that adds a field changes the schema: its Constraints then let the agent change `schema/output.schema.json` and `tests/test_schema.py`, and its done-when runs run 1's tests too.
