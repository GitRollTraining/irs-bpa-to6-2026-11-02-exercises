# Answer: the extractor's model and the agent's two levels

| Choice | Answer | Reason |
|---|---|---|
| The extractor's model | `gpt-6.1-sol`, with reason `capability`. | `gpt-6-luna` gave an amount for note 0104, which names none, in two of its five replies (null in the other three, as in exercise 2.2); `gpt-6.1-sol` gave null in all five. Replies may differ, but an amount that the note does not state is a failure in any reply; the null rule reduces such failures but does not end them (sections 2.1 and 2.2). The extractor starts with the cheaper model and moves up only for a failure that the evaluation set shows the other model fixes. `gpt-6-luna` does not hold the score, 16 of 20 notes to `gpt-6.1-sol`'s 17, so this one note is enough. `gpt-6.1-sol` is slower and costs three times as much, so its reason is capability (section 2.3). |
| Task 1: notes that name two amounts or two tax years | `codex -c model_reasoning_effort=medium` or `claude --effort medium`, with reason `capability`. | Its one rule goes to the model with every note, so it can change any reply, and its notes 0105, 0122 and 0137 are the set's edge cases. Work that you must verify on the whole set gets a higher level than work that you read line by line. Start at medium, not high: the top level can overthink, so test it before you rely on it (section 2.3). |
| Task 2: three tests of bad replies | `codex -c model_reasoning_effort=low` or `claude --effort low`, with reason `speed`. | Three short tests in one file read no note and call no model, and you read every line. Small work that you review yourself gets the lowest level, which is the fastest and the cheapest (section 2.3). |

The check also accepts high for task 1 with low or medium for task 2, because it reads only that task 1's level is above task 2's. It accepts cost as the reason for task 2, the command of either agent, and both commands in one cell at the same level. It accepts no model but `gpt-6.1-sol`, no reason but capability for `gpt-6.1-sol` and for task 1, and no level but low, medium or high, written in a command. Passing the check shows that the table matches the course's answer; it does not show that the choices hold on the evaluation set.
