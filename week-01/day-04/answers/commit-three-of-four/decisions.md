# Answer: the three changes to commit, and the one to leave out

| Change | Answer | Reason |
|---|---|---|
| `extractor.py`, `tests/test_extractor.py`, `README.md` | Stage each, and commit them. | `../agent-session.txt` asks for three changes: a log line for each failed reply, its test, and a `README.md` row about the log. The agent's report names the same three. You choose which changes go in (section 4.1, the table under "Skipping staging lets an agent's stray edit in.", row Who chooses). |
| `model.py` | Do not stage it. It stays changed on disk, in no commit. | Its two new lines in the function `ask` write each note sent to the model into the log, so line 1 of `logs/extractor.log` holds the whole text of note 0104. The request says "Write the note's number only, never its text", and the agent's report does not name this change: it is a debugging print. The lab's `README.md` also says that `model.py` is "not edited in the lab". When you stage by path, it can stay out (section 4.1, the same table, row The debugging print). |
| `logs/` | Add the line `logs/` at the end of `.gitignore`. Stage `.gitignore`, and commit it. | A commit of `logs/` keeps a whole note in the history, and a pushed commit is very hard to take back. The line stops Git listing and adding `logs/`, so a later `git add .` or `git add -A` cannot stage it. Committed, it does so in each clone (section 4.1, the heading "Keep the logs out: a pushed commit is very hard to take back."). |
| How to stage | `git add extractor.py tests/test_extractor.py README.md .gitignore`. In the notebook, the same four paths in `files`. | `git add` with paths stages only those files. `git commit -a` stages every tracked file that changed, so `model.py` goes in too; `git add -A` and `git add .` do the same (section 4.1, the same table, row What it stages). |

The check also accepts one commit or a commit for each change, `.gitignore` in the same commit or in its own, and any commit message. It accepts `model.py` put back with `git restore model.py`, or put away with `git stash push model.py`, as a stash is not part of the history. It accepts any line that keeps each file of `logs/` out of Git, such as `logs`, `/logs/`, `logs/*` or `*.log`, with `logs/` left on disk or removed. Passing the check does not test the code: it does not run the tests, which pass with or without the change to `model.py`.
