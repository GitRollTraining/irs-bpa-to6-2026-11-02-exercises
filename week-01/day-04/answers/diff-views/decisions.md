# Answer: four views of the agent's change, and what your commit holds

| View or move | Answer | Reason |
|---|---|---|
| `git diff --name-status` | `M extractor.py` only. | The plain form compares the files on disk with the staging area, so it misses each change that is already staged: here `prompts/system.txt` and `tests/test_extractor.py`, which the agent staged (section 4.3). |
| `git diff HEAD --name-status` | All three files. Unstage `prompts/system.txt` with `git restore --staged prompts/system.txt`: its change stays on disk, in no commit. | This form compares the files on disk with the last commit, staged or not, so it shows `prompts/system.txt`, which the agent's report leaves out. The directing prompt says "Change no other file", and a file outside what it allows is a finding before you read a line of it. For the same reason, `git diff --exit-code HEAD -- tests/` catches this run's staged test change, and `git diff --exit-code -- tests/` misses it (section 4.3). |
| `git add extractor.py`, then `git diff --staged --name-status` | `extractor.py` and `tests/test_extractor.py`. | `--staged` compares the staging area with the last commit, so it shows exactly what the commit will hold. The directing prompt asks for both changes, but the agent did not stage `extractor.py`, and without it the new test fails (section 4.3). |
| `git diff HEAD^ HEAD --name-status`, after `git commit -m "Fail a reply whose amount is negative"` | The same two files. | `HEAD` is now your commit and `HEAD^` the one before, so this form shows what your commit changed (section 4.3). |

The check reads your commits and the staging area, not the forms that you ran, so passing does not show that you read each view. It also accepts `prompts/system.txt` staged, unstaged, or restored with `git restore prompts/system.txt`, if no commit holds it; any change to `extractor.py` and any new test, if each test of the start stays and all the tests pass; and any number of commits. Leaving `prompts/system.txt` out does not make its change wrong: it can go into a later commit that a directing prompt asks for, after you score the fields on the evaluation set again, because the model reads the system prompt with every note (day 3).
