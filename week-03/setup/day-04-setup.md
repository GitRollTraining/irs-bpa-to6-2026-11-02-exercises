# Set up Thursday on the Workstations (week 3, day 4)

For the trainer. Thursday's three exercises run in each learner's Google Workstation terminal, with the Databricks CLI and Codex, against the class's Databricks workspace. Thursday makes no table: it reads Monday's `course.returns` tables and the eight tables Wednesday's notebook wrote in each learner's schema `course.learner_NN`. Do these steps before class, in order.

## Before Thursday

1. **Get the files.** On your own Workstation, in a terminal in the course folder, run `git pull`. The folder `week-03/day-04` and the files `week-03/setup/day-04-*` are there.
2. **The Databricks CLI on every Workstation.** On one learner's Workstation configuration, in a terminal, run `databricks -v`. It must print a version of 0.205.0 or above ("This version should be 0.205.0 or above", Databricks' CLI tutorial). If it prints `command not found`, the CLI is not installed or not on the path: have the Workstation configuration changed before class, for every learner.
3. **The workspace address.** Write the workspace URL on the board, or in the day's post, as `https://` and the host. Learners type it in exercise 1, step 3.
4. **Try the browser sign-in from a Workstation.** On a learner's Workstation configuration, run `databricks auth login --host <workspace-url>`, type `course` as the profile name, and sign in in the browser. Then run `databricks auth profiles`: `course` must show `YES` under Valid. If the browser sign-in cannot complete from the Workstation, use the token fallback (step 5) for the class, and tell the course team.
5. **The token fallback.** A learner whose sign-in fails makes the same profile with a personal access token. In the workspace: the user name in the top bar, **Settings**, **Developer**, **Manage** beside **Access tokens**, **Generate new token**. On the Workstation: `databricks configure --profile course`, then the workspace URL at the prompt **Databricks Host** and the token at **Personal Access Token**. Databricks recommends OAuth "Where possible", so this is the fallback only. The learner never pastes the token into Codex, a file in the course folder, or a chat.
6. **The right to run jobs, and job compute.** Exercise 2 runs `databricks jobs submit` with `week-03/day-04/exercise-02-run-wednesday-as-a-job/job.json`. The file names no compute, so the run takes the workspace's default ("serverless compute is the default for all tasks that support it"). Check that serverless compute for jobs is on for the workspace, and that the learners may run jobs. If it is not on, add a cluster to the file's task before class (`existing_cluster_id`, the class compute's id), commit, and tell the course team.
7. **The path in job.json.** The file names each learner's copy of Wednesday's notebook as `/Workspace/Users/<user name>/irs-bpa-to6-2026-11-02-exercises/week-03/day-03/wednesday-tables`, with no `.ipynb`: a notebook in the workspace is named without it (to confirm, item 4 below). The learner writes the user name; the rest is the course's. Open one learner's Git folder in the workspace. Check that the folder's name is `irs-bpa-to6-2026-11-02-exercises`, and that the notebook's full path (on its menu, copy its full path) matches, with or without `.ipynb`. If a part differs, change `job.json` and commit before class.
8. **Codex at its default settings.** On a learner's Workstation, start `codex` in `week-03/day-04/exercise-03-codex-checks-the-sets`, ask it to run `databricks catalogs list -p course`, and check that it asks before it runs the command. If it runs it without asking, the Workstation's Codex settings are not the default: type `/permissions` to see them, and have them reset before class. In class, a learner whose Codex runs a `databricks` command without asking stops it with Ctrl+C and calls you.
9. **Wednesday's tables in each learner's schema.** Run `databricks tables list course learner_NN -p <your profile>` for two or three learners. Each schema should hold `return_table`, `dependents`, `w2s`, `features`, `feature_record`, `train`, `valid` and `test`. A learner whose schema is empty runs exercise 2 first: the job writes the tables.
10. **The fallback transcript.** `week-03/setup/day-04-codex-transcript.md` is the course's run of six proposed commands (one without `-p`, one `jobs delete`). Read it once. Learners use it when their own Codex run proposes no command to judge.

## In class

- Demo before exercise 1: the same commands as exercise 1, in the same order: `databricks -v`, the mistyped `databrick -v`, `databricks auth login`, `databricks auth profiles`, `databricks catalogs list`, `databricks tables -h`, `databricks tables list course returns`, `databricks tables get course.returns.return_header`; `echo $?` after each. Read `total_tax_amt` in the JSON: it has no comment. The learners read `total_income` and their second column.
- Demo before exercise 2: submit `job.json` with your own two values, `--no-wait`, then `jobs get-run` until `status.state` is `TERMINATED`. Use your own copy of Wednesday's notebook.
- Demo before exercise 3: ask Codex whether `course.returns.return_header` has the column `exam_changed_tax`. Decline one command, and say which of the four questions decides it.
- No exercise uses MCP. See below.

## The MCP demo, for the trainer only

A Databricks SQL MCP server, switched on by a workspace administrator, connected to your own Codex before class. In Codex, type `/mcp` to see it ("In the composer, type /mcp to view connected servers.", OpenAI's Codex MCP page, https://developers.openai.com/codex/mcp, opened 2026-11-13; it now places this under the desktop app, so try it in the terminal before class). Ask exercise 3's question once, and show the tool call beside the CLI command that does the same. Databricks marks some of these servers Beta.

## After class

Nothing to reset in the workspace. A learner who did the optional part of exercise 3 has a saved job in their name: they may delete it with `databricks jobs delete <job id> -p course`, after the four questions.

3. **Exercise 2: the run starts, on job compute, as the learner.** Proposed: `databricks jobs submit --json @job.json --no-wait -p course` prints the run id at once, and the run uses serverless compute for jobs. Pages: https://docs.databricks.com/aws/en/dev-tools/cli/reference/jobs-commands; https://docs.databricks.com/aws/en/jobs/compute.
4. **Exercise 2: the notebook path, and what the run writes.** Proposed: the path of step 7, without `.ipynb`, reaches the learner's copy (if the run says the notebook is not found, add `.ipynb` and try again); the run writes the eight tables again with the same row count in `features`; `jobs get-run` shows `status.state` `TERMINATED` and `termination_details.code` `SUCCESS`. 5. **Exercise 3: Codex asks before each `databricks` command.** Proposed: at its default settings Codex stops before a command that needs the network, so each `databricks` command waits for the learner. Page: https://developers.openai.com/codex/agent-approvals-security ("Codex asks for approval to edit files outside the workspace or to run commands that require network access.").
6. **Exercise 3: a run that Codex finishes in time.** Proposed: Codex proposes `tables list` and `tables get` commands and gives an answer within the exercise; write down which commands it proposed, and how its approval prompt offers to decline. Page: as item 5.
